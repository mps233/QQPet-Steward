**A3. `tests/conftest.py`** —— **隔离是重中之重**

```python
"""测试隔离：绝不污染真实 runs/ 与 config.yaml。

背景：本项目所有进度/状态都写在 runs/ 下（见 docs/review/07-进程间契约.md），
历史上的测试教训是"涉及计数时要把进度文件重定向到临时目录"（见 AGENTS.md）。
本 conftest 自动完成这件事，避免每个测试自己处理。
"""
import shutil
import sys
from pathlib import Path

import pytest

ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(ROOT))


@pytest.fixture(autouse=True)
def isolate_runs(tmp_path, monkeypatch):
    """把 src.progress / src.queue_status / src.status_cache 的文件常量重定向到 tmp。"""
    fake_runs = tmp_path / 'runs'
    fake_runs.mkdir()

    mods = []
    for name in ('src.progress', 'src.queue_status', 'src.status_cache',
                 'src.instance', 'src.hire_quota'):
        try:
            mods.append(__import__(name, fromlist=['*']))
        except Exception:
            pass      # 模块不存在或导入失败不阻塞（渐进迁移）

    for m in mods:
        for attr in dir(m):
            if attr.isupper() and isinstance(getattr(m, attr, None), Path):
                p = getattr(m, attr)
                if 'runs' in str(p):
                    monkeypatch.setattr(m, attr, fake_runs / p.name,
                                        raising=False)
    yield fake_runs


@pytest.fixture
def repo_root() -> Path:
    return ROOT
```

## B. CI 工作流

### 修复

`.github/workflows/check.yml`（新增）

```yaml
name: check

on:
  push:
    branches: [main, master]
  pull_request:

jobs:
  python:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.13'          # 与 .venv 实际版本保持一致
      - name: 语法检查（全量）
        run: |
          find . -name '*.py' -not -path './.venv/*' -not -path './node_modules/*' \
            -print0 | xargs -0 python3 -m py_compile
      - name: 安装测试依赖
        run: python3 -m pip install -r requirements-dev.txt
      - name: 单元测试
        run: python3 -m pytest -q
      - name: 既有离线自检
        run: python3 tools/test_state_freshness.py --no-gui || true

  frontend:
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: web
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci --no-audit --no-fund || npm install --no-audit --no-fund
      - name: 类型检查
        run: node node_modules/typescript/bin/tsc --noEmit
      - name: 构建
        run: node node_modules/vite/bin/vite.js build
```

**设计取舍**：

- `py_compile` 全量扫，零依赖、秒级，能拦住语法错误（这是最低成本的第一道闸）
- 前端用 `node node_modules/...` 直调（与 `FRONTEND_PITFALLS.md:164-168` 的交付前检查一致），不依赖全局 PATH
- `test_state_freshness.py` 用 `|| true` —— 它需要设备环境，CI 里跑不全，先不阻塞
- **布局断言（C 节）暂不进 CI** —— 它需要 headless Chrome 且依赖 dashboard 在跑，放本地更务实

### 验收标准

1. 故意提交一个语法错误 → CI 变红。
2. 故意改坏一个测试 → CI 变红。
3. 正常提交 → CI 全绿。

## C. 布局验证自动化（最高价值）

### 问题

`web/FRONTEND_PITFALLS.md:10` 明确写着：

> 改任何涉及**高度 / 定位 / overflow / 容器层级**的 CSS 或 JSX，提交前必须跑探针量数值。

`:40-52` 给出了完整方法（同源 iframe + headless Chrome），`:104` 给出了具体断言步骤 —— **方法完备，但全部人工执行**。

后果（实测）：`app.css` 占全部 web 提交的 **61%**、占全部 fix 提交的 **80%**；约 **45%** 的提交在修布局与触摸；同一个高度链错误**犯过 3 次**。

### 修复

**04 文档的 F 节已给出完整可执行脚本**（`tools/layout-check.sh` + `tools/assert-layout.py`），本节不重复，只说明**接入方式**与**为什么这是回报最高的一项**：

| 断言 | 防住的是哪次历史事故 |
| --- | --- |
| P1 `.home` 高度 ≈ 视口高 | "修回被我改坏的整页高度"（犯过 2 次） |
| P2 总览页 `.home` 不溢出 | "总览页又能多滑一点"（`.drawer` 溢出导致） |
| P3 `main` 直系子全为 `div.page-slot` | 有人往骨架插新 wrapper（A 节禁招） |
| **P4 选择器命中数 > 0** | "内页背景变淡黄色 —— 直系子选择器被转场容器打断"（**静默失效，无任何报错**） |

P4 是其中最有价值的：它把**"改结构 → 选择器静默失效 → 样式回退"**这类最难发现的错误变成可自动检测项。

**接入**：

```json

"check:layout": "bash ../tools/layout-check.sh",
"check:layout:phone": "bash ../tools/layout-check.sh --sizes '360x640 390x844'"
```

```bash

bash ../tools/layout-check.sh --sizes 390x844 || [ $? -eq 2 ]
```

并在 `FRONTEND_PITFALLS.md:164-171` 的"交付前最低检查"清单里加一行：

```
node node_modules/typescript/bin/tsc --noEmit
node node_modules/vite/bin/vite.js build
bash ../tools/layout-check.sh --sizes 390x844      # ← 布局类改动必跑
```

### 分阶段落地（重要）

**先只跑手机三档（320/360/390）**。768 与 844×390 在修完 04 文档 E 节之前**预期失败** —— 让 CI/脚本长期标红会让人习惯性忽略它，反而失去意义。

### 验收标准

1. 改一处 `.home` 的高度 → 脚本 P1 失败。
2. 往 `main` 里插一个 wrapper → P3 失败。
3. 把 `app.css` 里某个 `main section[data-page]:not(...)` 规则删掉 → P4 失败。
4. 什么都不改 → 全 PASS。

### 回归风险点

- 脚本**不能替代真机**：headless 里 `env(safe-area-inset-*)` 恒为 0（`PITFALLS:56`），"屏幕底下露出一个 safe-bottom 背景"这类问题测不出来。脚本定位是"防结构回归"。
- 探针页写在 `web/dist/assets/` 下会被 `emptyOutDir` 清掉 —— 脚本每次重建它，所以没问题；但**不要**把它提交进仓库。

### D2. `AGENTS.md` 拆分方案

它现在混装了四类内容：

| 类别 | 特征 | 去向 |
| --- | --- | --- |
| ① 架构说明书（文件职责、模块关系） | 描述"现在是什么" | `docs/ARCHITECTURE.md` |

**关键规则（防再次膨胀）**：

> `AGENTS.md` 只放**约束**（"必须做什么"），不放**描述**（"现在是什么"）与**历史**（"曾经怎样"）。
> 每加一条前先问：这是约束还是说明？说明去 `ARCHITECTURE.md`，历史去 `PITFALLS.md`。

**为什么必须拆**：80358 字节 > 65536 预算 → **被截断 15KB**。也就是说，AI 代理读到的是**不完整**的 `AGENTS.md`，而被截掉的恰好是后半部分（往往是约束条目）。这直接损害了它作为"约束"的功能。

```python
# src/config_schema.py（新增）
"""配置项的单一声明源。

每个字段声明一次：段 / 键 / 类型 / 默认值 / 取值约束 / 是否热加载 / 前端控件类型。
config.yaml 的读写、src/settings.py 的 DEFAULTS 与 validate_field、
前端 settings-schema 的生成，全部从这份声明派生。
"""
from dataclasses import dataclass
from typing import Any, Literal

@dataclass(frozen=True)
class Field:
    path: str                       # 'care.interval_seconds'
    type: Literal['int', 'str', 'bool', 'hhmm', 'enum']
    default: Any
    doc: str = ''
    choices: tuple = ()             # enum 用
    hot: bool = True                # 是否支持热加载（False = 需重启）
    control: str = 'text'           # 前端控件：text/number/switch/select/time_range

FIELDS: tuple[Field, ...] = (
    Field('care.interval_seconds', 'int', 60, '护理检查间隔（秒）', control='number'),
    Field('care.method', 'enum', 'ocr检测', '护理方式', choices=('ocr检测', '一键护理'), control='select'),
    # ...
)
```

然后写一个生成脚本，产出 `web/src/lib/settings-schema.ts` 与 `src/settings.py` 的 DEFAULTS 表。

### 修复：结构化日志 + 关联 id（最小改造）

```python
# src/logctx.py（新增）
"""跨进程可关联的日志上下文。

背景：调度器是独立子进程（scenarios/runner.py），dashboard 是另一个进程，
两边日志无共同标识 —— 排查"用户点了一次保存，为什么调度器没反应"时无法串联。
"""
import contextvars
import uuid

_req = contextvars.ContextVar('req_id', default='-')

def new_req_id() -> str:
    """为一次外部触发（HTTP 请求 / 调度轮次）生成短 id。"""
    rid = uuid.uuid4().hex[:8]
    _req.set(rid)
    return rid

def req_id() -> str:
    return _req.get()
```

在 `log()` 里带上：

```python
def log(msg: str, *a, **kw) -> None:
    line = f'[{time.strftime("%H:%M:%S")}][{req_id()}] {msg}'
```

调用点：

- `dashboard.py` 的 `do_GET`/`do_POST` 开头 `new_req_id()`
- `runner.py` 每轮调度开头 `new_req_id()`
- 跨进程传递：写 `queue_status.json` 时带上当前 `req_id`，dashboard 展示时可对照

**收益**：一条日志行 `[11:44:03][a3f9c21b] 设置保存(来自 192.168.1.5): 提交 {...}` 就能与调度器侧的 `[11:44:07][a3f9c21b] 收到 reload.signal，重载配置` 对上。

### 验收标准

1. 在仪表盘改一次配置 → `grep <req_id> runs/logs/*.log` 能在 dashboard 与调度器两侧都找到对应行。
2. 日志格式变化不破坏现有解析（**注意**：`dashboard.py` 的 `work_eta` 用正则解析日志 —— 见 07 文档 C 节，改日志格式前必须先做那一步）。

### 回归风险点

- **改日志格式会破坏 `work_eta` 的日志正则**。所以顺序是：先做 07 文档 C 节（把状态改为直写字段），再改日志格式。
