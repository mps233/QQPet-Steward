## B. 缓存策略失效：hash 文件名白白浪费

### 问题

```

dashboard.py:1492        self.send_header('Cache-Control', cache)
```

### 修复

```python
# before（dashboard.py:1575-1576）
if fp.is_file() and fp.is_relative_to(root) and fp.suffix.lower() in _NCT:
    self._send(200, _NCT[fp.suffix.lower()], fp.read_bytes())

if fp.is_file() and fp.is_relative_to(root) and fp.suffix.lower() in _NCT:
    # Vite 产物名带内容 hash（index-QWsv1vBJ.js）→ 内容变则 URL 变，可长缓存。
    # 不带 hash 的（如 /next/index.html 兼容别名）仍走 no-store，否则用户永远停在旧版本 ——

    hashed = re.search(r'-[A-Za-z0-9_-]{8,}\.', fp.name) is not None

```

## C. 无 gzip：470KB 明文每次全量下发

### 问题

```
$ grep -n "gzip\|Accept-Encoding\|Content-Encoding\|zlib" dashboard.py
（无输出，exit 1）
$ curl -s -H 'Accept-Encoding: gzip, deflate, br' -D - -o /dev/null http://127.0.0.1:8787/assets/index-QWsv1vBJ.js
HTTP/1.0 200 OK
Content-Type: application/javascript
Cache-Control: no-store
Content-Length: 470510        ← 无 Content-Encoding
```

### 修复

**C-1 顶部 import**（`dashboard.py:18-30` 导入区）补 `import gzip`（`re` 已在 `dashboard.py:22`）。

**C-2 模块级常量**（`dashboard.py:64` `DEFAULT_PORT` 附近）

```python
_GZIP_MIN = 1024                     # 小于此不压：省 CPU，收益也小
_GZIP_TYPES = re.compile(            # 只压文本类；png/jpg/woff2/mp4 已压缩，再压纯属浪费
    r'^(text/|application/(javascript|json|manifest\+json)|image/svg\+xml)')
```

**C-3 改 `_send`（`dashboard.py:1489`）**

```python
# before（dashboard.py:1489-1498）
def _send(self, code: int, ctype: str, body: bytes, cache: str = 'no-store'):
    self.send_response(code)
    self.send_header('Content-Type', ctype)
    self.send_header('Cache-Control', cache)
    self.send_header('Content-Length', str(len(body)))
    self.end_headers()
    try:
        self.wfile.write(body)
    except BrokenPipeError:
        pass

# after
def _send(self, code: int, ctype: str, body: bytes, cache: str = 'no-store'):
    self.send_response(code)
    self.send_header('Content-Type', ctype)
    self.send_header('Cache-Control', cache)
    # 文本类按客户端声明压缩（实测 index-*.js 470510 → 107851 B）
    if (len(body) >= _GZIP_MIN and _GZIP_TYPES.match(ctype)
            and 'gzip' in (self.headers.get('Accept-Encoding') or '')):
        body = gzip.compress(body, 6)
        self.send_header('Content-Encoding', 'gzip')
        # 同一 URL 会因 Accept-Encoding 返回不同字节：必须声明 Vary，
        # 否则中间缓存可能把 gzip 版本发给不支持的客户端。
        self.send_header('Vary', 'Accept-Encoding')
    self.send_header('Content-Length', str(len(body)))   # 压缩后重新取值 ✓
    self.end_headers()
    try:
        self.wfile.write(body)
    except BrokenPipeError:
        pass
```

三个要点：压缩必须在 `Content-Length` 之前完成（原 `1493` 就在 `end_headers()` 前，顺序天然兼容）；`Vary` 一定要发；HLS 分片**不走** `_send`（`_send_stream` 在 `dashboard.py:1535-1539` 手写响应头）→ 流不会被误压。

### 影响面与风险

只在客户端主动要求时压缩。每请求同步 CPU：470KB → level 6 约 5~10 ms，且 `immutable` 缓存命中后不再重复下载。

### 验收标准

```bash
# 传输字节数（不加 --compressed，避免 curl 自动解压）
curl -s -o /dev/null -w '%{size_download}\n' -H 'Accept-Encoding: gzip' \
     http://127.0.0.1:8787/assets/index-QWsv1vBJ.js
# 期望：≈107851（level 6 略大于 gzip -9 实测值）

curl -s -D - -o /dev/null -H 'Accept-Encoding: gzip' \
     http://127.0.0.1:8787/assets/index-QWsv1vBJ.js \
  | grep -iE 'content-encoding|vary|content-length'
# 期望：Content-Encoding: gzip / Vary: Accept-Encoding / Content-Length 为压缩后长度

curl -s -D - -o /dev/null http://127.0.0.1:8787/assets/index-QWsv1vBJ.js | grep -i content-encoding
# 期望：无输出（不支持 gzip 的客户端仍走明文）

curl -s -D - -o /dev/null -H 'Accept-Encoding: gzip' http://127.0.0.1:8787/icon-192.png | grep -i content-encoding
# 期望：无输出（图片不压）
```

### 回归风险点

忘记 `Vary` 会让某个中间代理成为故障源。压缩级别取 6 而非 9。**本节唯一"改错就炸"的点**：`Content-Length` 若被误放在压缩前，客户端会截断下载（页面白屏）—— 必须实测 `size_download`。

### 三个方案的取舍

使用场景是"**手机在内网看**"（`README.md:4`）。评估必须从这点出发。

| 方案 | 手机可用 | 用户成本 | 安全收益 | 判定 |
| --- | --- | --- | --- | --- |
| ① 绑 `127.0.0.1` + 反代 | ✗ 需自建反代 | 高（与本项目"纯标准库零依赖"冲突） | 高 | **不作为默认**；作为可选 `--host` 提供 |
| ② 可选 token（`?k=` 换 Cookie） | ✓ | 低 | 中高（挡住同网段"顺手看看"与端口映射） | **推荐** |
| ③ 仅加启动横幅警告 | ✓ | 零 | **零** | 作为补充，单独不成立 |

**推荐 ②+③**：默认不启用 token（完全向后兼容），启用后横幅明确提示；同时提供 `--host`。理由直接 —— 方案 ① 用"砍掉核心用例"换安全，方案 ③ 只是把 README 已经写过的话搬到终端，而本项目的核心教训正是"**写下来 ≠ 约束**"。

**E-3 门禁方法**（加在 `class Handler` 内、`_send` 之前）

```python
    def _authorized(self) -> bool:
        """token 门禁。未设 TOKEN 时始终放行（向后兼容）。

        手机输入长 token 很痛，所以支持 `/?k=<token>` 一次性换取 Cookie：
        校验通过后 302 到**去掉 k 的同一 URL**（其余 query 如 ?tab=log&sub=reward 保留），
        并种下 Cookie —— 这样 token 不会留在地址栏、浏览器历史和 Referer 里。
        """
        if not TOKEN:
            return True
        for part in (self.headers.get('Cookie') or '').split(';'):
            k, _, v = part.strip().partition('=')
            if k == 'qpet_key' and hmac.compare_digest(v, TOKEN):
                return True
        u = urlparse(self.path)
        given = (parse_qs(u.query).get('k') or [''])[0]
        if given and hmac.compare_digest(given, TOKEN):
            rest = [(k, v) for k, v in parse_qsl(u.query) if k != 'k']
            clean = urlunparse(u._replace(query=urlencode(rest)))
            self.send_response(302)
            self.send_header('Location', clean or '/')
            self.send_header('Set-Cookie',
                             f'qpet_key={TOKEN}; Path=/; Max-Age=31536000; SameSite=Lax')
            self.end_headers()
            return False         # 已写响应，调用方必须直接 return
        self._send(401, 'text/plain; charset=utf-8',
                   '需要访问令牌：请用 http://<主机>:8787/?k=<令牌> 打开一次'.encode('utf-8'))
        return False
```

```python
def _check_dist() -> None:
    """启动时校验前端产物：缺失或过期都给出可操作提示（只警告，不阻断服务）。"""
    idx = BASE / 'web' / 'dist' / 'index.html'
    hint = 'cd web && ./build.sh'
    if not idx.is_file():
        print(f'[dashboard] ⚠ web/dist 未构建：主页会返回 503。修复：{hint}',
              file=sys.stderr, flush=True)

    try:
        newest = max(
            (p.stat().st_mtime
             for p in (BASE / 'web' / 'src').rglob('*') if p.is_file()),
            default=0.0,
        )
        for extra in (BASE / 'web' / 'vite.config.ts', BASE / 'web' / 'index.html'):
            if extra.is_file():
                newest = max(newest, extra.stat().st_mtime)

        return
    if newest > idx.stat().st_mtime:
```

**F-2 提交前拦截**：`tools/check_dist.py`（新增脚本）

```python
#!/usr/bin/env python3
"""校验前端产物 web/dist 是否存在且不比 web/src 旧。

用法：
    python3 tools/check_dist.py            # 只报告，始终 exit 0
    python3 tools/check_dist.py --strict   # 缺失/过期 → exit 1（供 pre-commit / CI 用）
"""
import sys
from pathlib import Path

BASE = Path(__file__).resolve().parent.parent
DIST = BASE / 'web' / 'dist'
SRC = BASE / 'web' / 'src'
HINT = 'cd web && ./build.sh'


def main() -> int:
    strict = '--strict' in sys.argv
    idx = DIST / 'index.html'
    if not idx.is_file():
        print(f'✗ web/dist 未构建（主页会 503）。修复：{HINT}', file=sys.stderr)
        return 1 if strict else 0
    newest = max((p.stat().st_mtime for p in SRC.rglob('*') if p.is_file()), default=0.0)
    for extra in (BASE / 'web' / 'vite.config.ts', BASE / 'web' / 'index.html'):
        if extra.is_file():
            newest = max(newest, extra.stat().st_mtime)
    if newest > idx.stat().st_mtime:
        print(f'✗ web/dist 已过期（web/src 有更新的文件）。修复：{HINT}', file=sys.stderr)
        return 1 if strict else 0
    print('✓ web/dist 存在且比 web/src 新')
    return 0


if __name__ == '__main__':
    sys.exit(main())
```

## 实施顺序

按"收益/风险比"排序，前 3 步一次做完、一次验收：

1. **A（构建配置）→ 重建 `web/dist`**。同时解决 C 的体积与 D 的 map 产出，是所有收益的源头。
2. **B（缓存头）+ C（gzip）**。两处都在 `dashboard.py` 的 `_send` 附近，一次改完一次重启。
3. **D-2（白名单删 `.map`）**。一行改动，与第 2 步同一次重启生效。
4. **重启 8787 并手机实测一次**：`kill $(lsof -nP -iTCP:8787 -sTCP:LISTEN -t) && ./dashboard.sh`。手机端确认：页面能开且是新版本、实时画面正常（HLS 走 `_send_stream`，不受 `_send` 压缩影响）。
5. **E（可选 token）**。独立改动、默认关闭，可延后。
6. **F（启动自检 + pre-commit）**。长期防线，最后落地。

> 第 1 步做完就拿到 **77%** 的流量收益与全部源码暴露面的关闭 —— 如果只做一件事，做第 1 步。
