## A. 触摸目标低于 44×44

### 问题描述

| 元素 | 当前值 | 行号 | 390px 实测 | 缺口 |
| --- | --- | --- | --- | --- |
| `.mcb` 任务启用勾选框 | `19u × 19u` | `app.css:970-971` | **20.6 × 20.6px** | 差 23px |
| `.navhead .backbtn` 返回钮 | `34u` | `app.css:1585` | **36.8px** | 差 7px |
| `.sw` 开关 | `46 × 26px`（裸 px） | `app.css:1178` | **26px** 高 | 差 18px |
| `.minibtn`（"发送测试通知"） | padding 2px/8px + 11px 字 | `app.css:1199-1202` | 高约 **17px** | 差 27px |
| `.idfold` 状态面板折叠 | `17u` 高 | `app.css:490` | **18.4px** | 差 26px |
| `.idring` 状态环 | `27u` | `app.css:525` | **29.3px** | 差 15px |

**最要紧的是 `.mcb`**：它是**全项目唯一的任务启停开关**（`TaskList.tsx` 的勾选框），却是全屏最小的可点元素之一。而它同时承担了两种手势 —— 点击切换启用、长按拖动排序，误触代价高。

参照：`.rbtn` 圆钮是 `42u ≈ 45.5px`（`app.css:257`），勉强达标；`.fab` 功能按钮 `50×70u`（`app.css:747`）达标。**说明项目里已有正确尺寸的先例，只是没有统一规则。**

### 修复方案

**建立硬规则**（写进 `web/FRONTEND_PITFALLS.md` 的检查清单）：

> 可点元素的**视觉尺寸可以小，但命中区不得小于 44×44 CSS px**。
> 用伪元素扩热区，不改视觉。

**A1. 通用扩热区工具类**（`app.css` 新增，放在基础段附近）

```css
/* 扩热区：视觉不变，命中区撑到 44×44。
   用法：给可点元素加 class="hit44"，元素自身需 position:relative（或由本类提供）。 */
.hit44{ position:relative }
.hit44::after{
  content:'';
  position:absolute;
  /* 居中扩到至少 44px（用 min() 保证小元素也能撐满，大元素不缩小） */
  width:max(100%, 44px);
  height:max(100%, 44px);
  left:50%; top:50%;
  transform:translate(-50%,-50%);
  /* 只吃事件，不画东西 */
  background:transparent;
}
```

> ⚠️ **不能用这一招的元素**（改用行内热区或直接放大视觉）：
> 1. 祖先有 `overflow:hidden` 且元素紧贴边缘 —— 热区会被裁掉（`.tasklist` 滚动容器内的元素尤其要查）。
> 2. 兄弟元素间距 < 44px —— 热区会互相重叠，先点到的赢（`.funcbar` 内的 `.fab` 间距 20u≈21.7px，**就不能用**）。
> 3. `position:fixed` 元素内部的绝对定位锚点 —— 会改变包含块。

**A2. 勾选框 `.mcb`**（`app.css:970`）—— 视觉升档 + 整行热区

```css
/* BEFORE */
.mcb{
  width:calc(var(--u) * 19);height:calc(var(--u) * 19);
  border-radius:calc(var(--u) * 6);background:rgba(0,0,0,.10);
  flex:none;cursor:pointer;position:relative;user-select:none;
}

/* AFTER —— 视觉升到 22u（23.8px），热区靠行内右端区域撑满 */
.mcb{
  width:calc(var(--u) * 22);height:calc(var(--u) * 22);
  border-radius:calc(var(--u) * 7);background:rgba(0,0,0,.10);
  flex:none;cursor:pointer;position:relative;user-select:none;
}
/* 行级热区：整行右端 56u 宽、44px 高的透明层也触发勾选 */
.task-row .mcb-hit{
  position:absolute; top:0; bottom:0; right:0;
  width:calc(var(--u) * 56);
  min-height:44px;
  background:transparent;
}
```

> 更省事的做法：把勾选框的 **父行**做成点击目标（整行点击 = 切换启用），勾选框只做视觉指示。**但要先确认**拖动排序的守卫逻辑（`FRONTEND_PITFALLS.md` 第 5 节提到"拖拽守卫 `e.target.closest('.mcb')` 时不启动拖拽"），改成整行点击后该守卫需要同步调整，否则点行会变成拖拽起手。

**A3. 开关 `.sw`**（`app.css:1178`）

```css
/* BEFORE */
.sw{ /* width:46px;height:26px; ... */ }

/* AFTER —— 保留视觉（26px 高），用命中区扩到 44px */
.sw{ position:relative }
.sw::after{
  content:'';position:absolute;left:50%;top:50%;
  transform:translate(-50%,-50%);
  width:max(100%,44px);height:44px;background:transparent;
}
```

**A4. `.minibtn` / `.idfold` / `.idring` / `.backbtn`**

统一加 `.hit44` class；其中 `.backbtn`（36.8px）已接近，可只补高到 44px。

### 影响面与风险

- 扩热区会改变**点击命中优先级**。改动后必须回归：任务行点击、拖动排序、状态环展开、折叠面板。
- `.idring` 与 `.idfold` 都在资料卡内且相邻 —— 扩热区后可能重叠，需检查间距。
- `.sw` 用 `::after` 覆盖后，若 `.sw` 自身有 `::after`（做成开关圆点），会被覆盖 —— **先 grep 确认**。

### 验收标准

1. 390×844 视口下，用探针量每个可点元素的有效命中区：
   ```js
   // 单行 JSON 输出（PITFALLS 第 2 节：不能带缩进）
   JSON.stringify([...document.querySelectorAll('.mcb,.sw,.minibtn,.idfold,.backbtn')]
     .map(el => { const r = el.getBoundingClientRect()
       const a = getComputedStyle(el, '::after')
       const h = Math.max(r.height, parseFloat(a.height) || 0)
       const w = Math.max(r.width,  parseFloat(a.width)  || 0)
       return { cls: el.className, w: Math.round(w), h: Math.round(h), ok: w >= 44 && h >= 44 } }))
   ```
2. 断言**全部 `ok: true`**。
3. 真机（iOS + Android）逐一点击，确认无误触、无"点了没反应"。

### 回归风险点

- `FRONTEND_PITFALLS.md` 第 3 节：**iOS 手势 × 滚动容器** —— 热区扩大后，滚动容器内的元素更容易被判定为"交互"而非"滚动"，可能让滚动变粘。**必须真机验证滚动流畅度**。
- 热区重叠区（如 `.sw` 与相邻文字）会抢事件，需确认没有把只读文本变成可点。

## B. 字号阶梯与对比度

### 问题描述

**B1. 字号无阶梯，0.5 级差手调**

实测取样：`9 / 9.5 / 10 / 10.5 / 11.5 / 12 / 12.5 / 13 / 14 / 15 / 17 / 20`（u 值）。

0.5 级差说明是**逐处手调**的结果，改一处字号无法推及其他。小于 11px 的正文（`.dsub` 9u、`.tghint` 9u、`.mdet` 10u）在手机上难以辨认。

**B2. 对比度实算（WCAG 相对亮度公式）**

| 组合 | 位置 | 实算 | 判定 |
| --- | --- | --- | --- |
| `--sub #9A7A4A` on `--card #F9EFDE` | `app.css:59` | **3.51:1** | ✗ 低于 AA 4.5:1 |
| `--sub #9A7A4A` on 白 `#FFFFFF` | 内页 | **3.99:1** | ✗ |
| `--accent #FF990F` 底 + 白字 | `app.css:1238` | **2.14:1** | ✗ 严重不达标 |
| `--text #723900` on `--card` | `app.css:57` | 8.01:1 | ✓ |

第 3 行即日志页「收益记录」选中胶囊 —— 截图中可见的橙底白字胶囊。

### 修复方案

**B1. 五级字号 token**（`app.css` 的 `:root` 段新增）

```css
/* 字号阶梯：废除 0.5 级差与 <11px 正文。
   用法：font-size:var(--fs-sm) —— 不再写 calc(var(--u) * 9) 这类一次性值。 */
--fs-xs: calc(var(--u) * 11);
--fs-sm: calc(var(--u) * 12);
--fs-md: calc(var(--u) * 14);
--fs-lg: calc(var(--u) * 17);
--fs-xl: calc(var(--u) * 20);
```

映射规则：

| 旧值 | 新 token | 说明 |
| --- | --- | --- |
| 9 / 9.5 / 10 / 10.5 | `--fs-xs`(11) | 小于 11 一律提升 |
| 11.5 / 12 / 12.5 | `--fs-sm`(12) | |
| 13 / 14 / 15 | `--fs-md`(14) | |
| 17 | `--fs-lg`(17) | |
| 20 | `--fs-xl`(20) | |

**B2. 对比度修复**

```css
/* BEFORE */
--sub:#9A7A4A;          /* 3.51:1 on --card */

/* AFTER —— 实算 5.55:1 */
--sub:#7A5A28;
```

```css
/* BEFORE */
.logctl button.on{background:var(--accent);border-color:var(--accent);color:#fff}   /* 2.14:1 */

/* AFTER —— 深棕字 on 橙，实算 5.42:1 */
.logctl button.on{background:var(--accent);border-color:var(--accent);color:#5A2D00}
```

备选（若想保留白字观感）：

```css
.logctl button.on{background:#B45309;border-color:#B45309;color:#fff}   /* 白字 on 深橙，实算 5.02:1 */
```

> 两案取舍：**深棕字方案**保持橙色鲜亮、改动最小；**深橙底白字方案**视觉更"按钮化"，但会与原 `--accent` 产生第二个橙色，需评估是否引入新 token。

### 影响面与风险

- `--sub` 是全局次级文字色，改深后**19 处使用点**全部变深（`grep -c 'var(--sub)'` 先统计确认）。深色模式若有独立取值（`prefers-color-scheme:dark` 段）需同步。
- 字号提升会让部分容器（如 `.dsub` 所在的三行状态卡）高度增加 → 与 01 文档的状态卡改动叠加时，**必须一起验收**。
- `.mdet`、`.tghint` 等窄容器内字号提升可能导致换行/截断。

### 验收标准

1. 用脚本复算所有前景/背景组合的对比度（见文末脚本），断言**全部 ≥ 4.5:1**。
2. `grep -n 'font-size:calc(var(--u) \* \(9\|9\.5\|10\|10\.5\)' web/src/styles/app.css` 返回空（无 <11 的字号残留）。
3. 真机截图对照：长文本（状态卡的 `dsub`、日志页元信息、通知页说明）确认无截断、无溢出。
4. 深色模式（`prefers-color-scheme:dark`）下重跑一次对比度检查。

### 回归风险点

- `FRONTEND_PITFALLS.md` 第 4 节：**改 CSS 前先 grep 有没有 `@media` 里的同名规则**。`--sub` 若在 `@media(max-width:360px)` 内有覆盖，只改基规则在真机上无效（`.advlist .ai` 就吃过两次这个亏）。
- 字号变化属于"布局类改动"，按 PITFALLS 第 1 节必须量 `.home` 高度。

## 附：对比度复算脚本

```bash
python3 - <<'PY'
def lum(h):
    h = h.lstrip('#')
    if len(h) == 3: h = ''.join(c*2 for c in h)
    r, g, b = [int(h[i:i+2], 16)/255 for i in (0, 2, 4)]
    f = lambda c: c/12.92 if c <= 0.03928 else ((c+0.055)/1.055)**2.4
    return 0.2126*f(r) + 0.7152*f(g) + 0.0722*f(b)

def cr(a, b):
    la, lb = lum(a), lum(b)
    hi, lo = max(la, lb), min(la, lb)
    return (hi + 0.05) / (lo + 0.05)

PAIRS = [
    ('--sub 修复后 on --card', '#7A5A28', '#F9EFDE', 4.5),
    ('--sub 修复后 on 白',     '#7A5A28', '#FFFFFF', 4.5),
    ('选中态 修复后',          '#5A2D00', '#FF990F', 4.5),
    ('白字 on 深橙 备选',      '#FFFFFF', '#B45309', 4.5),
    ('--text on --card',       '#723900', '#F9EFDE', 4.5),
]
for name, fg, bg, need in PAIRS:
    v = cr(fg, bg)
    print(f'{"PASS" if v >= need else "FAIL"}  {name:26s} {v:5.2f}:1  (需 {need})')
PY
```

实测输出（修复方案已验证通过）：

```
PASS  --sub 修复后 on --card       5.55:1  (需 4.5)
PASS  --sub 修复后 on 白           6.32:1  (需 4.5)
PASS  选中态 修复后                5.42:1  (需 4.5)
PASS  白字 on 深橙 备选            5.02:1  (需 4.5)
PASS  --text on --card             8.01:1  (需 4.5)
```
