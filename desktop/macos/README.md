# macOS 本机应用

一个 App 包含仪表盘界面、Python 后台和调度器。打开后自动启动并连接随包本机后台，
直接进入主界面，无需填写服务器地址、保留源码目录或另外安装 Python。
菜单栏面板可查看状态、启动/暂停/恢复/停止调度器，也可打开完整主界面。
界面以 `web/` 为唯一真源，构建时将其产物与后台一起打入 App。

## 运行方式

- App 内含 `QQPetRuntime`，以 `dashboard`、`scheduler`、`career-sync` 子命令
  分别运行后台、调度器与职业识别。它们共享一套随包 Python 环境和资源。
- 仪表盘服务只绑定本机回环地址；App 自动连接和登录，访问凭据不暴露给界面脚本。
- 兼容已有本机托管服务，采用现有实例，不重复启动或抢占其 PID。
- 关闭窗口后 App 留在菜单栏；菜单中的“退出 App（托管继续在后台）”退出控制端，
  不会主动停止仪表盘或调度器。停止任务请用面板或主界面的“停止”。
- App 自动将后台交给用户级 launchd 作业 `ai.qqpet.dashboard.app` 托管，
  调度器由仪表盘按需启动。用户无需另行运行安装脚本。
- 已有 `ai.qqpet.dashboard` 托管继续被采用，App 不强停或替换这个旧作业。

## 数据与资源

只读内容存于 `QQ Pet Dashboard.app/Contents/Resources/backend/`：

- `QQPetRuntime` 与 `_internal/` 内的 Python、项目代码和本机依赖；
- `web/dist/`、`static/`、默认配置、福袋图片模板；
- PP-OCRv6 tiny 检测/识别模型与 v4 方向分类模型；
- uiautomator2 的 JAR/APK、ADB 与需要的动态库；
- minitouch 的四个 Android ABI、Frida 客户端和 Java 桥；
- 已准备好的 Frida 17.17.0 Android arm64/x86_64 离线服务端压缩包。

配置、日志和进度写入用户数据目录，默认：

```text
~/Library/Application Support/QQPetCopilot/
  config.yaml
  runs/
```

`QQPET_DATA_DIR` 可显式指定数据根目录；App 采用已有服务时沿用那个服务的数据。
App 包内不保存用户配置、访问码、通知凭据或运行进度。

控制端在自己的 Application Support 目录中记录采用的数据根，并保存按构建指纹区分的
后台副本，供 launchd 使用：

```text
~/Library/Application Support/ai.qqpet.dashboard.desktop/
  data-root.txt
  backends/<build-fingerprint>/
```

因此移动或重命名 App 不会让已托管后台的可执行路径失效；升级后台也不会覆盖用户数据。

## 构建条件

- macOS、Xcode Command Line Tools；
- 本机架构的 Rust、Node.js 与项目 `.venv/bin/python`；
- `requirements.txt` 运行依赖，及 `desktop/macos/requirements-build.txt` 构建依赖；
- 已有 `web/dist/`，或已安装 `web/node_modules`、可运行 `web/build.sh`；
- 本机已有 Android platform-tools 的 `adb`，可由 `QQPET_BUILD_ADB` 指定；
- 三个 OCR 模型已位于 `models/rapidocr/` 或 `runs/models/rapidocr/`。

缺少模型时可运行 `tools/fetch_ocr_models.py`。minitouch 与可选 Frida 离线资源可用
项目的 `tools/fetch_minitouch.py`、`tools/fetch_frida_server.py` 准备。
构建只选择三个公开 OCR 模型和指定资源，不将整个 `runs/` 或无关模型打入 App。

## 构建与验证

从仓库根目录执行：

```bash
desktop/macos/scripts/build-macos.sh
```

脚本先确认前端产物，再运行 `scripts/build-runtime.sh` 冻结 Python 后台，
最后使用本地 Tauri CLI 构建完整 App。缺少 PyInstaller 或 Frida 运行依赖时，
runtime 构建脚本将其安装到项目虚拟环境。

成功后打印固定的项目内产物路径：

```text
desktop/macos/target/release/bundle/macos/QQ Pet Dashboard.app
```

Python runtime 产物固定为 `desktop/macos/target/runtime/QQPetRuntime/`，
由 Tauri 放进 App 的 `Contents/Resources/backend/`。缓存校验覆盖相关源码、依赖版本、
前端与图片、模型、ADB 和控制资源；缓存命中仍运行隔离自检。
目录内的 `.build-fingerprint` 随包保存，用于选择 launchd 后台副本版本。

Rust 默认使用 `desktop/macos/target/` 缓存，也支持调用时设置 `CARGO_TARGET_DIR`。
首次构建失败时，脚本会用临时 target 重试，将成功的 App 复制回同一产物路径；
只替换这个构建目标，不安装到 `/Applications`，也不替换其他临时 App。
构建脚本不安装或卸载 launchd；App 在实际启动时准备自己的托管作业。

开发验证时，前端更新先重建 `web/dist/`，Python 后台更新需重启对应服务；
完整 App 的前后端资源随包分发，修改后需重新构建 App。App 会继续采用已运行的
本机后台，重新构建本身不会替换那个进程。

仅构建后台：

```bash
desktop/macos/scripts/build-runtime.sh
```

完整 App 的结构与离线自检：

```bash
desktop/macos/scripts/verify.sh \
  "$PWD/desktop/macos/target/release/bundle/macos/QQ Pet Dashboard.app"
```

校验检查 bundle id、图标、Mach-O 主程序及随包 runtime，再运行
`QQPetRuntime self-test`。自检仅使用临时数据根，检查导入、资源、OCR 模型校验和、
配置写入与冻结版调度器命令，初始化真实 ONNX OCR 引擎并识别一张纯白测试图。
自检禁用网络，不连接设备、不启动 TG、不读取或修改真实运行进度。
它不代替主界面、菜单栏操作和真实设备流程的实际验证。

`gen/`、`permissions/autogenerated/`、`target/` 是本目录的生成产物，已由本目录的
`.gitignore` 忽略。

## 使用

1. 打开 App，等待本机后台准备完成。
2. 在设置中选择 Android 设备，确认 QQ 宠物停在自己的主页，并调整任务与每日配额。
3. 在首页或菜单栏面板点「启动」开始托管；也可暂停、恢复、停止调度器。
4. 关闭窗口后可从菜单栏重新打开；退出 App 不等同于停止任务。

后台启动失败会在界面显示错误；详细日志位于数据根目录下的
`runs/dashboard_console.log`。端口被占用时不抢占其他进程。

## 安全与发布边界

- App 沿用仪表盘的访问验证；本机原生宿主处理登录 Cookie，不把访问码硬编码进包。
- 启动页、菜单栏面板和仪表盘使用独立 WebView；仪表盘页没有 Tauri 命令授权，
  `withGlobalTauri` 保持关闭。
- 仪表盘 WebView 只允许留在本机服务 origin，站外链接交给系统浏览器。
- 前端与后端均随 App 构建，运行时不依赖源码或构建工具。
- 当前脚本生成未签名 `.app`，不包含 `.dmg`、Developer ID 签名或公证发布流程；
  正式分发仍需补齐这些步骤。
